Fix first

Bugs found during the review

These are in the live code today. The first three can lose clock-in or clock-out times, so hours go missing from payroll. Each fix is small and self-contained.

Data loss

Clocking in and out with no signal loses the clock-out

An offline clock-in is saved on the phone without a record id. When that person then clocks out, still offline, the saved clock-out points at "no id". When the phone comes back online, the update matches nothing and is thrown away. The shift stays open until the auto-close runs.

app.html:2601, 2774, 843 · fix: match the queued clock-out on the clock-in's idempotency_key
Data loss

A tap on weak signal is dropped, not saved for later

The app only queues a clock event when the phone reports it is fully offline. On one bar of signal the phone still says "online", the request fails, and the only thing left is an error message. The tap is gone.

app.html:2768, 2779 · fix: if the request fails with a network error, add it to the offline queue
Data loss

Saved clock events only sync when the connection changes

The queue is sent only when the phone switches from offline to online. If the app is closed while offline, saved events can sit on the phone for days. After a reload the app shows "Not clocked in" even though a clock-in is waiting, which invites a second clock-in.

app.html:854, 2127 · fix: send the queue on app open and when the app comes back to the front, and show a "waiting to sync" chip
Wrong number

"Pending approvals" and "Open shifts" always show 0

These Overview tiles ask the database for a count, then read the (empty) list instead of the count. The Approvals badge in the sidebar is also always hidden, so managers never see the nudge.

dashboard.html:9665, 9677 · fix: read count instead of data.length
Broken button

The Library tile in the staff app never loads

The tile calls a function that doesn't exist, so it spins forever. The real function has a different name.

app.html:1147 · fix: loadResources → loadStaffResources
Staff app · app.html

What changes for staff

Staff open the app mainly to clock in. Today the clock button is below the fold on a busy day, and a profile reminder can cover it. The plan puts the clock and the shift in charge of the home screen.

S1

Shift-aware clock card at the top

Shows "Your shift started 1h 18m ago" in red when someone is late, or "Starts in 2h 15m". Once clocked in: a live hours:minutes:seconds timer, a progress bar, break due and finish time. Built from shift data the app already loads, so no extra database calls.

UX
S2

Visible sync status for clock events

A chip under the button: "All clock events synced", or "1 clock-in saved on this phone, syncs automatically". Staff and managers can see that nothing is lost. Goes with bug fixes 1 to 3.

Data safety
S3

Location check as an in-app sheet

Replaces the browser's "OK / Cancel" pop-up in the middle of clocking in. Shows how far away the phone is, lets the person tap a reason, and offers "Try location again".

UX
S4

Tabs open instantly, then refresh

Each tab keeps its last result in memory and shows it straight away while fresh data loads in the background. Pull down to refresh. The Today tab refreshes itself when the app comes back to the front. Fewer spinners and fewer repeat database calls.

Speed
S5

Links and the back button work

Push notifications already send staff to /app#rota, but the app ignores the #rota part. Reading it opens the right tab, and the phone's back button moves between tabs.

UX
S6

Clear confirmation on clock in and out

A short vibration and a "Clocked in 14:03" toast. After an error the button is reset instead of stuck on "Getting location…".

UX
S7

Forms keep what was typed

Holiday requests and pay queries save a draft if the sheet is closed by accident. The submit button is disabled while sending, so a double tap can't create two requests.

Data safety
S8

Banners stop covering the controls

The profile reminder moves to the Profile tab. The offline banner sits in the page instead of floating over the messages bar.

Staff app · making it fun

Clock-in and clock-out moments

Today clocking in or out gives no feedback: the button just changes colour. These short moments say thank you, and they appear only after the clock event has been saved, so they never slow it down or get in its way.

F1

Clock in: tick, confetti and a friendly message

The button pulses, a green tick draws itself, a small burst of confetti, and a message such as "You're in, Jordan! Have a great shift". A short double vibration confirms it. Chips show "1 min early" and streaks like "5 on-time shifts in a row". Being late shows no chip, never a telling-off.

Fun
F2

Clock out: a wave and your shift in numbers

"Thanks Jordan, great work today" with a waving hand, and the hours worked, break and week total counting up. The message changes through the day ("enjoy your evening" after 5pm).

Fun
F3

Milestones get the big confetti

First shift, 10th, 25th, 50th, 100th, 250th and 500th. Kept rare so they stay special.

Fun
F4

Messages that fit the person and the time

"Morning, early bird" before 7am, "Let's go ⛽" or "Have a great shift" on the forecourt. If the phone has no signal, the moment still plays and adds "Saved on this phone, will sync".

Fun
F5

Small touches around the app

Cards slide in gently when the app opens, and the tab icon bounces when tapped. The clock button shrinks slightly under the thumb.

Fun
F6

"ON TIME" stamp for clocking in and out on time

Clocking in on time (or early) turns the message into "Right on time, Jordan! Have a great shift", and a green "ON TIME ✓ 13:58" stamp slams onto the card with a thud, a buzz and confetti. Clocking out within 10 minutes of the shift end gives "Shift done, right on time. Thank you, Jordan!" with the same stamp and "🔥 5 full shifts on time in a row". Staying later gives "Thanks for staying on 💛 Stayed 20 min extra". Clocking in late still gets a friendly "You're in", just without the stamp or confetti.

Never in the way

The moment plays after the clock event is saved or queued. It closes itself after 4 seconds, or with one tap.

Light and quick

About 4 KB of plain JavaScript and CSS, with no animation library. The confetti uses a single canvas that removes itself when finished.

Respects phone settings

If "reduce motion" is on, the message still shows but there's no confetti, bounce or count-up. Vibration only works on phones that support it.

Streaks without extra load

The streak and shift count come from one small count query that runs after the clock-in is saved. The moment doesn't wait for it.

Staff app · rewards for the forecourt team

Badges, shout-outs, weekly recap, birthdays and training

Built around what matters on a Shell forecourt: GO+ scans, RLA training, customer feedback, turning up on time and helping the team out. Staff only ever see their own progress, and nothing negative is shown or animated.

R1

Badges on the Profile tab

Nine badges to start: On the dot (5 on-time shifts), GO+ Hero (weekly GO+ target), GO+ Legend (4 weeks running), Fully trained (all RLA training green), Customer star (a 5/5 review on your shift), Team player (covered a shift), Early bird (10 shifts before 7am), Century (100 shifts) and Appreciated (5 shout-outs). Locked badges show progress, like "37 of 100". A new badge unlocks full-screen with rays, a shine and confetti.

No new tables
R2

Manager shout-outs

A "🙌 Thank" button next to each person on the dashboard. The manager picks a reason (covered a shift, great with customers, GO+ star, spotless site, smashed the delivery, went the extra mile) and adds a line. The staff member gets a push notification and a celebration in the app, and the shout-out stays on their Profile. It can also appear on the site team's Today screen.

1 new table
R3

Monday weekly recap

A short story-style recap the first time they open the app on a Monday: hours worked, on-time shifts and streak, GO+ against the 25% target, the site's customer score with a real customer comment, and badges earned. Tap to skip ahead, and it never shows again that week.

No new tables
R4

Birthdays and work anniversaries

On someone's birthday, the first time they open the app balloons float up the screen, a "Happy birthday, Jordan! 🎂" banner drops in from the top and the phone buzzes. They can tap the balloons to pop them. Each pop makes a soft "pop" sound, with a little confetti burst and a counter ("🎈 8 popped"). One golden balloon glows and floats up more slowly. Popping it reveals a hidden message, such as the manager's note "There's cake in the staff room". Popping every balloon gives "🎉 You got them all!" and a big burst of confetti. On their start-date anniversary they get "1 year at SJC Fuel Services!" with balloons and confetti. A card stays on the Today tab all day to replay it. It plays once per day and only for that person, so nobody's date of birth is shown to anyone else.

No new tables
R5

Training complete

When the weekly RLA report shows nothing outstanding, the next time they open the app a graduation cap is thrown in the air and lands on a certificate with their name, the modules they finished, their site and the date. Then comes confetti and "🎓 Fully trained badge unlocked". If some modules are done but others are still owed, a smaller card slides up: "Module complete: Fire Safety. Just 1 to go, you're nearly there!", with a progress bar filling up. It compares the latest RLA report with the one before, so no new data is needed, and each report is celebrated once.

No new tables

Where the data comes from

Badges and the recap are worked out from tables WorkHive already has: clock-ins, shifts, GO+ weekly scores, RLA training status and SMG customer feedback. Nothing new is stored for them.

The one database change

Shout-outs need one small new table (who, to whom, reason, message, date) with the same security rules as the rest: staff read their own, managers write for their sites. It's the only schema change in the whole plan, and it's added, never changing existing tables.

Fair and kind

No rankings of people against each other. Nobody's low numbers are shown to colleagues. A missed target just leaves the badge locked, with the progress bar.

Light

About 11 KB for all four features. The pop sound is generated on the phone, so there is no sound file to download, and the confetti is shared with the clock-in moments. The recap loads once a week, and badges load only when the Profile tab opens.

Managers and owner · dashboard.html

What changes on the dashboard

The dashboard is one 27,000-line file that runs every panel's code on every visit, with 459 database queries mostly run one after another. These changes make the daily jobs quicker without rewriting any panel.

D1

Correct counts and a "needs attention" row

Fixes the 0 counts. Adds one row of actionable items above the tiles (approvals, cash not banked, flagged end-of-day checks, open shifts). Each one opens the right panel.

Bug fixUX
D2

Every panel has its own link

/dashboard#cash opens Cash Banking. Refreshing keeps you on the same panel, and panels can be bookmarked. It goes through the existing switchPanel, so owner-only and HR-only checks still apply.

UX
D3

Ctrl+K search that covers everything

The current search lists 17 panels and misses every forecourt panel (sales, cash, recon, checks, GO+, stock, RPI, wastage, visits, bank). The new version adds them plus actions and people, and only shows panels the user can open.

UX
D4

Filter, sort and export on any table

One small helper adds a filter box, sortable column headers and CSV export to tables. Today only payroll sorts, and only five panels export.

UX
D5

In-app dialogs with Undo

Replaces 16 alert, 72 confirm and 12 prompt pop-ups. Rejections get reason chips, and approvals get a 10-second Undo instead of an "Are you sure?" step.

UX
D6

Background checks pause when the tab is hidden

Eleven timers poll the database, most every 60 seconds, even in a background tab. Pausing them while the tab is hidden and running them together on one timer cuts requests. A "Live · updated 12s ago" pill shows how fresh the data is.

Speed
D7

Load the map library only when a map opens

Leaflet loads before the page can start (line 2589), but only Site Visits uses it. Loading it on demand gives a quicker first screen.

Speed
D8

Run Overview queries in parallel

Live attendance, late today and open shifts wait for each other one by one. Running them together with Promise.all makes the Overview appear sooner, with the same queries and results.

Speed
D9

Warn before leaving unsaved changes

Switching panels or closing the tab mid-edit loses the input without warning. Only Site Visits saves a draft today. Add a warning to all panel forms.

Guardrails

How we build it without losing data or speed

Added on top, not rewritten

New code lives in small separate files loaded after the page (defer). Existing functions keep working. The only edits to current code are the five bug fixes, each a few lines.

No database or permission changes

No changes to existing tables, columns or security rules (the only addition is one new table for shout-outs, see Rewards). Every save still goes through the same Supabase calls, so security rules and audit logs are unchanged.

Saved copies are for display only

Instant tabs show the last copy, then always reload. Clock state, pay and approvals are never decided from a saved copy.

Size and speed budget

All new code together stays under 15 KB compressed. Page load time and number of requests are measured before and after each release, and must not get worse.

Tested before deploy

New unit tests for the offline queue and the count fix sit next to the existing ones in test/. Everything runs through npm test and the pre-deploy check.

Switch off per feature

Each upgrade has an on/off flag, so any one can be turned off without a redeploy if something looks wrong.
